# Translation specialist MVP operator notes

The v2 worker translates through a separate private service. Start the translation backend and its protected loopback/tunnel first. The gateway and worker use `TRANSLATE_V2_ENABLED=true`, `TRANSLATE_V2_SPECIALIST_BASE_URL=http://127.0.0.1:18404` (the client appends `/v1/translate`), `TRANSLATE_V2_SPECIALIST_API_KEY=<service token>`, `TRANSLATE_V2_SPECIALIST_MODEL=tencent/Hy-MT2-1.8B`, `TRANSLATE_V2_SPECIALIST_TIMEOUT_SECONDS=120`, and `TRANSLATE_V2_SPECIALIST_CONTEXT_TOKENS=8192`. Keep the token outside Git. The model value must equal the backend `model` response exactly. The URL must be private; public URL, embedded credentials and absent token fail closed. These settings do not change `/ai/translate`.

When using the image route, also configure the existing `TRANSLATE_V2_OCR_*` settings. Set `TRANSLATE_V2_OCR_CORRECTION_SUPPORTED=false` for this translation-only specialist. The OCR stage then retains raw OCR blocks, reports `OCR_CORRECTION_REJECTED`, and sets `needs_review=true`; it makes no automatic editing claim. A supported correction service requires the separate Linch runner and keeps its strict edit validation.

Run one standalone worker with `SESSION_STORE_BACKEND=memory`, empty `REDIS_URL`, the v2 settings, and `python -m secai_gateway.translation.worker`. The web app and worker must share the v2 job DB/artifact paths. The web API remains anonymous under `/ai/v2/translate` and keeps the documented upload/status/result contract. The worker needs no DuyTa provider for direct translation in unsupported-correction mode.

For opt-in DuyTa delegation, construct a separate `LinchRunner` with `SESSION_STORE_BACKEND=memory`, configure the same v2 specialist settings, and call `await runner.complete("translation_orchestrator", "Translate from en to vi: Hello CVE-2024-12345", None)`. That profile alone registers `translation_specialist`; `chat` and legacy `translate` tool registries remain unchanged. The tool accepts structured `text`, `source_lang`, and `target_lang`, applies v2 literal protections, and returns the specialist output. The runner rejects a response without a successful specialist tool call and returns the tool's validated text exactly. A real LLM invocation is still required to prove the model chooses the tool in deployment.
