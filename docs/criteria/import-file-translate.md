## Fixed functional corpus and translation rubric

Minimum 30 IDs, not 90 independent samples: 8 TXT (UTF-8, BOM, UTF-16 LE, UTF-16 BE, CP1258, mixed newline, technical, long); 8 DOCX (paragraph/table/header/footer/footnote/sections/Unicode/long, combinations allowed); 6 DOC (VI, EN, table, header/footer, footnote, long); 8 invalid (empty, corrupt, mismatch, PDF, oversize, binary TXT, unsafe archive, unsupported). All fixtures synthetic/public/permitted. Each valid sample has source golden blocks, target language, protected spans with offsets and occurrences, and required semantic propositions annotated before execution. Include EN→VI and VI→EN.

For every valid sample/round: block coverage/order 100%; protected spans 100%; target-language prose judged correct by independent bilingual tester; all annotated propositions retained with no contradictory/extra propositions; terminology glossary matched, except documented legitimate inflection of prose only. Literal-only blocks excluded from language judgments. Tester marks each proposition correct/incorrect, no vague overall impression. Any omitted technical condition, negation, number, warning or security impact is FAIL. This rubric is a bounded-corpus quality gate, not a claim of perfect translation on all future inputs.

Manifest schema minimum: `sample_id, feature, stratum, input_path, sha256, source_lang, target_lang, expected_outcome, expected_error, source_golden_path, protected_spans_path, propositions_path`. Three seeds recorded before run, result cache disabled. Each run row includes SHA(s), sample_id, seed/round, HTTP statuses, job terminal/error, elapsed time, coverage, literal precision/recall, rubric result and evidence reference. Pacing may honor quotas; testing throttles uses separate cases. Never edit expected/ground truth to make output pass; genuine labeling correction versions corpus and invalidates affected comparisons.
