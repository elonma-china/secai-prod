# OCR model selection: measured candidate 1 of at most 3

Status 2026-10-04: **not production accepted**. PaddleOCR-VL-1.6 passed numeric raw OCR thresholds on a deterministic 62-image synthetic corpus, but failed Arabic logical reading order on separate calibration images with three bounded prompts. Language-qualified fixture review, corrected OCR, full translation jobs, and complete acceptance-run GPU/latency evidence remain open. Only Paddle has been loaded or inferred so far. This report does not use vendor scores as local evidence.

- Existing Vast instance 53846446, A100 80GB, torch 2.11+cu130, transformers 5.13.1, Python 3.12.13. Vast reports host GPU PIDs but container-local `/proc` PID; runtime identifies the unique new GPU PID on the same GPU UUID after its CUDA context starts, fails closed on ambiguity, and gates `free >= max(2048, 9216 - owned_MiB)` before each inference plus own usage <=7168 MiB.
- Frozen 30-image VI/EN/technical manifest was committed at `404f93a90958027fe0d2b386c45477b724adffc6` **before** its 90 successful inference calls. Source text was authored before rendering; Pillow with libraqm shaped Arabic bidi and font cmap checks rejected missing glyphs. Visual spot checks were done for Arabic mixed LTR tokens and Chinese. Qualified native-language review is still required.
- Original 30 synthetic images: 8 clear VI, 4 clear EN, 8 technical, 6 rotated synthetic pages, 4 low contrast/blur. Expanded corpus adds four each zh/ja/ko/fr/de/es/ru/ar. The rotated images are **synthetic rotations**, not real phone photographs. There are 40 reference CVE and 40 IP occurrences across the expanded corpus. This limited corpus cannot establish broad real-world OCR quality.

Per-language micro/macro accuracy was identical across rounds: Arabic 71.6/77.8%, Vietnamese 97.4/98.0%, and EN/ZH/JA/KO/FR/DE/ES/RU 100/100% on these four-image or small synthetic subsets. The technical subset was 97.6/95.0%. **Arabic reading order is a functional concern**: image `a62` reference logical order is `الثغرة CVE-2024-3018 تخص 192.0.2.18.`; raw model output was `.192.0.2.18 تخص CVE-2024-3018 الثغرة.`. The scorer preserves that error; it must not reverse text globally or edit the reference to hide it. A separate tiny-font calibration image also merged `CVE-2024-1234 192.0.2.1` into `CVE-2024-12341920.2.1`; it is outside the frozen corpus and remains a challenge case.

The gateway `preprocess_image` path was then applied to the same 62 frozen source images, yielding prepared-manifest SHA-256 `400c0c76aed770ea4405f70284dc98cc4d4f97d29c3d4bf19fed67bb9a4215bc`; 14 synthetic rotated images changed geometry. In `evals/translation_ocr/results/paddle-prepared-62/round-{0,1,2}.jsonl` all 186 prepared-path requests returned HTTP 200 with the **same** raw predictions and per-language scores as the direct-image run, including Arabic `a62`'s reversed group order. Their SHA-256 values are `5dc37374f232eefc3fb13cb4755f75a2ac4414b1210f6fcd9c2272cf42439a95`, `70f561cf143a65bdb2b78ff7bd1315dc0bfe14a1c4f51b04fa7899c100a8222c`, and `51a27ae1a02266e6b385e5d1afb41e9c92ccc2168c6aefe6d1d23c902ccc38b5`. Round 0 p95 was 10.002s/max 49.106s while OCR contended with live correction LLM calls on the shared GPU, so it is not an isolated latency comparison. Once those calls stopped, rounds 1/2 p95 were 5.872/5.832s. A sampler running from **before prepared inference**, but after model load, recorded 1,244 samples, minimum global free 7,586 MiB, maximum owned host-PID usage 2,418 MiB and no quota anomaly. Its full trace is `paddle-prepared-62/gpu-monitor.json`.

The separate Arabic prompt-calibration fixtures were frozen at commit `159d86a0613ebe819bbe6e988f2e5f6c8e48f8b7` before inference and are **excluded** from acceptance scoring. All three were rendered with libraqm bidi shaping and visually inspected. On each of `OCR:`, a generic natural-reading-order instruction, and an explicit Arabic logical-order instruction, Paddle emitted the text groups in visual left-to-right order. For `cal-ar-1`, reference logical order is `عنوان الخادم 203.0.113.7 مرتبط بالثغرة CVE-2023-4911.`; outputs were respectively `.CVE-2023-4911 مرتبط بالثغرة 203.0.113.7 عنوان الخادم عنوان`, `.CVE-2023-4911 مرتبط بالثغرة 203.0.113.7 عنوان الخادم عنوان.`, and `.CVE-2023-4911 مرتبط بالثغرة 203.0.113.7 عنوان الخادم`. Nine verbatim outputs and references are in `calibration/arabic/results.jsonl`; code-point accuracies ranged 2.6–18.9%, not a passed Arabic result. On the restart for this small run, a monitor was active **before model load** through all nine inferences: 366 samples, min global free 7,639 MiB, max owned allocation 2,366 MiB, no anomaly. This small run does not substitute for full acceptance-run resource evidence. The unqualified manually authored Arabic source text still needs native-language review.

An earlier attempted 90-call run produced 90 HTTP 503 because the service compared GPU host PID with container PID, charging own GPU usage as zero. That run is **invalid infrastructure evidence**, not an OCR quality result. The unique-new-host-PID guard was then installed and one request verified HTTP 200 before the 186-call run. Full acceptance-run GPU sampling and load/unload comparative incumbent latency probes remain pending; one-off post-load LLM/embedding/rerank calls each returned HTTP 200 but do not establish no regression.
