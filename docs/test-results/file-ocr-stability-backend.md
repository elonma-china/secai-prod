## Root causes and changes

| Area | Reproduced fault | Change and bounded outcome |
|---|---|---|
| OCR HTTP | `AsyncClient.post` consumed the entire response before the 2 MiB check; an unbounded stream reached a fourth chunk. | Stream raw response and stop reading as soon as bytes exceed 2 MiB. Malformed output fails; transient transport/502–504 retries remain bounded, nontransient HTTP errors do not retry. |
| Worker deadline | LLM retry loop reused the first remaining deadline, permitting a later attempt to run past the job deadline. | Recompute remaining time per call, including time spent waiting for the semaphore; return `PROCESSING_TIMEOUT` at the absolute job deadline. |
| OCR cancellation | The worker watched job cancellation only during LLM calls; an active OCR request could occupy its slot after cancellation. | Watch the full image pipeline and cancel its child request on job cancellation/deadline. Temporary preprocessing directories remain under the existing context manager. |
| OCR correction | `except Exception` treated a correction provider outage like an invalid edit proposal and silently translated raw OCR text. | Raw fallback remains only for malformed/invalid proposals. Provider/deadline errors now fail the job. |
| FOS-B01, independent review High | `httpx.Timeout` was an idle timer; a trickling 200 response could hold the OCR slot beyond 120s. | `a9edeaf` places one absolute call budget around OCR request, stream and retry backoff, inside the job deadline. Slow trickle returns failed `OCR_UNAVAILABLE` rather than hanging. |
| FOS-B02, independent review High | Linch defaulted to five model retries, OpenAI SDK to two, and Linch surfaced provider failures as an event that `LinchRunner.complete()` returned as empty output. | Worker startup sets both hidden retry budgets to zero, while `WorkerContext` owns the sole eligible retry. Worker-only strict transform handling maps Linch error events to typed provider errors; legacy runner construction keeps its previous behavior. Actual captured wire tests show 503/disconnect twice total, 401 once, and successful 503→200 recovery. |
| FOS-B03, independent review Medium | Raw `aiter_raw()` bytes were parsed as JSON, rejecting valid gzip; a compressed expansion could evade the decoded-size cap. | Stream gzip decoding with 2 MiB caps on both wire and decoded bytes; reject unsupported encoding, malformed gzip and expansion before JSON parsing. |
| Retry override | Configured `llm_max_retries` or `ocr_max_retries` above one could exceed FS-08's hard one-retry limit. | `4cbd458` clamps operational retries to one while keeping existing config/default behavior; override=3 regression changed from four sends to two. |
| FOS-R2-01, independent re-review High | Direct SIGTERM killed the local launcher without stopping its API/worker children; a second-child startup error could strand the first child. | `6101ecc` registers a SIGTERM stop flag before child startup and moves both launches inside one cleanup `finally`; direct-PID SIGTERM and partial-startup tests were red before, then **2 passed in 0.90 s**. |
| VG-F01, Vanguard Medium | Encrypted DOCX raised `RuntimeError` while opening a ZIP entry; the worker reported `INTERNAL_ERROR`. | `bef2e05` rejects encrypted ZIP entries before reading, returning `UNSAFE_DOCUMENT` through extractor, worker and public job status; failed result remains HTTP 409. |
| VG-F02, Vanguard Medium | Two processes setting SQLite WAL mode at the same time could raise `database is locked` on first startup. | `bef2e05` initializes WAL once per store with a bounded retry on locked/busy; per-transaction WAL switching was removed. Two-process same-key admission still resolves to one job. |

No dedicated translation model, Hy-MT client, specialist profile/tool or new routing path was added. Existing `translate_v2` and `ocr_correction` profiles remain tool-less on the existing Linch/DuyTa runner. Independent backend re-review confirmed FOS-B01/B02/B03 addressed; a subsequent scoped launcher re-review at `f70795c` confirmed FOS-R2-01 addressed without new findings. These reviews close their scoped code findings, not the feature acceptance gates.

Independent review of `db84964..bef2e05` in `docs/reviews/file-ocr-vanguard-fixes.md` (separate review worktree) closed VG-F01 and VG-F02 for their scoped criteria, including 60 synchronized fresh two-process starts and a persistent-lock retry-bound probe. The original Vanguard report retains its other blocked security evidence and a low-severity dependency-environment mismatch (`olefile==0.46` installed versus declared `>=0.47`). Persistent SQLite contention can still delay startup by up to roughly 20 SQLite waits of 30 seconds plus retry sleeps; this is an operator availability limit, not a quality or security PASS.
