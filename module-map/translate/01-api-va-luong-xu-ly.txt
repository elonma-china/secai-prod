# API và luồng xử lý dịch

## 1. Danh sách endpoint

| Nhóm | Method | Endpoint | Công dụng | Giao diện hiện gọi |
|---|---|---|---|---|
| Legacy | POST | `/ai/translate` | Dịch text, trả JSON | Không |
| Legacy | POST | `/ai/translate/stream` | Dịch text, trả SSE legacy | Không |
| V3 | GET | `/ai/v3/translate/languages` | Ngôn ngữ, hướng bật/tắt, giới hạn | Có, khi vào màn hình |
| V3 | POST | `/ai/v3/translate` | Dịch text, trả JSON | Không trong panel hiện tại |
| V3 | POST | `/ai/v3/translate/stream` | Dịch text, trả SSE theo đoạn | Có |
| V3 | GET | `/ai/v3/translate/openapi.json` | Schema riêng v3 | Không |
| V2 | POST | `/ai/v2/translate/files` | Nhận một TXT/DOCX/DOC, tạo job | Có |
| V2 | POST | `/ai/v2/translate/images` | Nhận một PNG/JPG/JPEG, tạo job OCR + dịch | Có |
| V2 | GET | `/ai/v2/translate/jobs/{job_id}` | Trạng thái, giai đoạn, tiến độ | Có, polling |
| V2 | GET | `/ai/v2/translate/jobs/{job_id}/result` | Kết quả job thành công | Có |
| V2 | DELETE | `/ai/v2/translate/jobs/{job_id}` | Yêu cầu hủy job | Có |

`/health` là endpoint hỗ trợ chẩn đoán chung, không chứng minh model dịch hoặc OCR hoạt động. V2 xuất hiện trong schema gateway; v3 có schema riêng, không dựa vào `/openapi.json` legacy để tìm v3.

### Vị trí và tham số của từng API

Đường dẫn tính từ root `secai-agent-gateway`:

| Endpoint | File định nghĩa / hàm | Tham số cần truyền |
|---|---|---|
| POST `/ai/translate` | `src/secai_gateway/api/routes.py` → `translate` | JSON nội dung (`text` hoặc alias), nguồn `source_lang`, đích `target_lang` hoặc `language`; `user_id` tùy chọn |
| POST `/ai/translate/stream` | `src/secai_gateway/api/routes.py` → `translate_stream` | Cùng body legacy trên |
| GET `/ai/v3/translate/languages` | `src/secai_gateway/api/multilang/routes.py` → `languages` | Không có body/tham số bắt buộc |
| POST `/ai/v3/translate` | `src/secai_gateway/api/multilang/routes.py` → `post_translate` | JSON bắt buộc `text`, `source_lang`, `target_lang` |
| POST `/ai/v3/translate/stream` | Cùng file/hàm `post_translate` | Cùng ba field v3; không thêm `stream` |
| GET `/ai/v3/translate/openapi.json` | `create_v3_app` đặt `openapi_url`, FastAPI sinh route | Không có tham số bắt buộc |
| POST `/ai/v2/translate/files` | `src/secai_gateway/api/translate_v2/routes.py` → `upload_file` / `_admit` | Multipart `file`, `target_lang` bắt buộc; `source_lang` tùy chọn; header `Idempotency-Key` tùy chọn |
| POST `/ai/v2/translate/images` | Cùng file → `upload_image` / `_admit` | Cùng multipart/header v2, file ảnh |
| GET `/ai/v2/translate/jobs/{job_id}` | Cùng file → `get_job` | Path `job_id` từ upload, không body |
| GET `/ai/v2/translate/jobs/{job_id}/result` | Cùng file → `get_result` | Path `job_id`, không body |
| DELETE `/ai/v2/translate/jobs/{job_id}` | Cùng file → `delete_job` | Path `job_id`, không body |

Legacy schema ở `api/schemas.py::LegacyRequest`; v3 ở `api/multilang/routes.py::Input`; v2 tự parse/validate multipart trong `_admit`. Source/target legacy không bắt buộc bởi schema, nên ví dụ dưới luôn chỉ định để có kỳ vọng rõ ràng. V3/v2 hiện không yêu cầu Bearer ở router dịch; đăng nhập website IAS là lớp ứng dụng bên ngoài và không được suy ra từ auth gateway.

**Phân biệt website thật với checkout:** `https://ias.id.vn/ai/translate` là đường dẫn trang web GET, không phải bằng chứng trang gọi POST legacy cùng path. Frontend IAS quan sát được là giao diện khác React Devspace trong repo. Login `/login` và các API web `/api/...` không được coi là API do gateway này định nghĩa mặc định — IAS có tầng proxy riêng `/api/ais/...` phía trước.

**Đã xác minh qua Network thật ngày 09/10/2026 (phần Dịch tệp/ảnh):** IAS gọi `POST https://ias.id.vn/api/ais/v2/translate/files`, `POST https://ias.id.vn/api/ais/v2/translate/images`, và poll trạng thái tại `GET https://ias.id.vn/api/ais/v2/translate/jobs/{job_id}` — tức IAS proxy tiền tố `/api/ais` trước đúng path v2 của gateway. Request có header `authorization: Bearer <JWT>` lấy từ phiên đăng nhập web (JWT chứa `usn: dev201`), khác với mô tả "v2 hiện là API ẩn danh" ở mục 3 — **qua tầng proxy IAS, v2 yêu cầu Bearer**; bản thân route gateway có thể vẫn ẩn danh nếu gọi trực tiếp, chưa kiểm lại trực tiếp gateway để so sánh. Chưa xác minh path proxy tương ứng cho `/ai/v3/translate*` (phần Dịch trực tiếp) do chưa bắt được request đó trong Network; nghi ngờ cùng mẫu `/api/ais/v3/...` nhưng không khẳng định.

**Lỗi 400 ngắt quãng khi poll job status — phát hiện thật ngày 09/10/2026:** polling `GET /api/ais/v2/translate/jobs/{job_id}` đang chạy ổn định (200) thì có các đợt ~12-50 request liên tiếp trả **400** (`text/plain`, body gần như rỗng/"Bad Request"), rồi tự phục hồi về 200 sau vài giây — lặp lại theo chu kỳ khi poll nhiều job đồng thời (4 job cùng lúc trong 1 phiên). Request header lúc 400 vẫn có Bearer hợp lệ — không phải lỗi thiếu auth. Nghi vấn: rate-limit/WAF phía proxy IAS trả sai mã 400 thay vì 429 theo đúng contract lỗi ở mục 5 bên dưới. **FE không hiện bất kỳ cảnh báo nào cho người dùng khi gặp chuỗi 400 này** — console chỉ log `Get translate job error`, UI vẫn hiển thị "Đang chờ xử lý..." như bình thường, giống hệt trạng thái đang chạy thật.

## 2. Dịch text v3

### Capability và ngôn ngữ

`GET /ai/v3/translate/languages` trả `languages`, `pairs`, `limits`. Mỗi hướng có `source_lang`, `target_lang`, `enabled`, `status`; mỗi ngôn ngữ có mã, tên, chữ viết và hướng chữ `ltr`/`rtl`.

| Ngôn ngữ | V3 | V2 |
|---|---|---|
| Việt | `vi` | `vi` |
| Anh | `en` | `en` |
| Trung giản thể | `zh-Hans` | `zh` |
| Nhật | `ja` | `ja` |
| Hàn | `ko` | `ko` |
| Pháp | `fr` | `fr` |
| Đức | `de` | `de` |
| Tây Ban Nha | `es` | `es` |
| Nga | `ru` | `ru` |
| Ả Rập | `ar` | `ar` |

V3 nhận alias `zh` rồi chuẩn hóa về `zh-Hans`. Không hỗ trợ `auto`, nguồn bằng đích hoặc hướng giữa hai ngoại ngữ. Khi nguồn khác Việt, UI chỉ cho đích Việt. Ngôn ngữ có trong danh sách không đồng nghĩa hướng đó đang bật.

### Request và response

POST JSON tới `/ai/v3/translate` hoặc `/ai/v3/translate/stream`:

```json
{
  "text": "Kiểm tra nhật ký bảo mật.",
  "source_lang": "vi",
  "target_lang": "en"
}
```

Cả ba field là chuỗi bắt buộc, không được rỗng/chỉ khoảng trắng. Schema input `extra="forbid"`: không thêm `user_id`, `stream` hoặc field legacy vào v3.

Response JSON thành công có cấu trúc sau; nội dung dịch và metadata là minh họa:

```json
{
  "translated_text": "Check the security log.",
  "source_lang": "vi",
  "target_lang": "en",
  "warnings": [],
  "metadata": {"request_id": "<id>", "chunks": 1, "attempts": 1}
}
```

SSE có `chunk` với `delta`, `index`, `total`, `warnings`; `final` chứa cấu trúc kết quả như JSON, rồi `data: [DONE]`. UI nối delta trong lúc chờ, cuối cùng thay bằng `final.translated_text`. Chỉ có HTTP 200 hoặc đã thấy vài đoạn không đủ xác nhận thành công. Thiếu `final` được client báo `STREAM_INCOMPLETE`; `event: error` sau khi mở stream vẫn là lỗi dù HTTP 200. Đây là stream theo đoạn đã kiểm tra, không phải cam kết stream từng token.

Cảnh báo `SOURCE_LANGUAGE_UNCERTAIN`/`TARGET_LANGUAGE_UNCERTAIN` nghĩa là chưa xác minh tự động đủ tin cậy; cần đọc bản dịch, không mặc định coi job thất bại. Text v3 hiện không lưu thành lịch sử dịch trên máy chủ. Hủy bằng UI ngắt request trình duyệt; không có endpoint DELETE text riêng.

### Giới hạn

Mặc định mã nguồn v3: 24.000 ký tự Unicode code point, 8.192 source token, 16 đoạn và deadline 120 giây. Luôn lấy giá trị thực từ capability. Độ dài ký tự và token khác nhau: văn bản dưới giới hạn ký tự vẫn có thể vượt token/budget xử lý. UI đếm bằng `Array.from(text).length`.

## 3. Job dịch tệp/ảnh v2

### Upload

Gửi `multipart/form-data`, mỗi POST có đúng **một** `file`, `target_lang` bắt buộc, `source_lang` tùy chọn (mặc định `auto`). UI hiện luôn gửi nguồn đã chọn. Không tự đặt boundary `Content-Type` khi dùng `FormData`.

Header `Idempotency-Key` tùy chọn ở API, UI luôn gửi: đúng 32 ký tự hex thường `[0-9a-f]`. Retry cùng upload giữ nguyên khóa để lấy lại job đã nhận; dùng lại khóa cho dữ liệu khác có thể trả `IDEMPOTENCY_CONFLICT`.

V2 chấp nhận nguồn `auto` và nguồn bằng đích ở tầng admission; không áp quy tắc strict v3 cho v2. Hai ngoại ngữ khác nhau bị từ chối khi khai báo nguồn cụ thể. UI chỉ cung cấp hướng Việt ↔ ngoại ngữ.

POST thành công trả **202**, gồm `job_id`, `kind`, `status`, `stage`, `progress`, `source_lang`, `target_lang`, `warnings`, `error`, timestamp, `status_url`, `result_url`. Đây là xác nhận tiếp nhận, chưa phải bản dịch.

```text
Chọn tệp → upload → queued → running → succeeded → lấy result → xem trước/tải
                                  ↘ failed
                     hủy → cancelling → cancelled
```

Polling GET trạng thái; nếu `failed`, đọc `error.code`; chỉ gọi result để lấy bản dịch khi `succeeded`. DELETE trả 202 là yêu cầu hủy; chờ trạng thái cuối, không coi 202 là đã hủy xong. Job đã kết thúc có thể trả 409 khi hủy. DELETE là hủy xử lý, không phải chức năng xóa lịch sử bản dịch đã hoàn tất.

### Kết quả

Result gồm `job_id`, `kind`, `status`, `source_lang`, `target_lang`, `translated_text`, `blocks`, `warnings`, `ocr`.

- `blocks`: ID, loại, thứ tự, `source_text`, `translated_text`, metadata để đối chiếu nội dung tài liệu.
- `warnings`: danh sách `{code, message, block_id}`.
- Ảnh có `ocr.raw_text`, `corrected_text`, `edits`, `needs_review`; phải so với ảnh gốc trước khi đánh giá bản dịch.
- UI tải TXT từ `translated_text`, JSON từ result; tải bằng Blob trên trình duyệt, không có endpoint download riêng.

Chưa có xuất lại DOCX/PDF giữ nguyên bố cục. Kết quả mặc định giữ 24 giờ sau khi job kết thúc (`TRANSLATE_V2_RESULT_TTL_SECONDS`); hết hạn trả 410 trong thời gian giữ tombstone, sau đó 404. Không chờ 24 giờ để test thường: kiểm theo ca có môi trường TTL ngắn riêng hoặc ghi chưa kiểm chứng.

### Quyền truy cập và giới hạn

Routes v2 hiện là API ẩn danh, không kiểm `user_id`/Bearer như project/session. `job_id` khó đoán đóng vai trò bí mật truy cập; ai biết ID có thể tra kết quả/hủy theo trạng thái. Không đưa ID thật/khóa idempotency vào báo cáo công khai. `user_id` của demo không tạo ownership riêng cho job dịch v2.

UI hiện giới hạn 5 tệp mới mỗi phiên, 4 dòng/trang, mỗi tệp tối đa 10 MiB; upload tự động sau chọn tệp. Giữ tối đa hai yêu cầu/job chưa giải quyết, upload cách nhau ít nhất 12,5 giây, polling ít nhất 4 giây/job và tuân theo `Retry-After`. Phiên lưu metadata/hàm băm/ID/khóa trong `sessionStorage`; không lưu bytes hay bản dịch. Reload cần chọn lại tệp chưa gửi, job đã có ID được tiếp tục tra.

Backend mặc định: 10 MiB/file, 11 MiB/request, 20 triệu pixel/ảnh, cạnh tối đa 10.000 px, 200.000 code point/tài liệu, 10.000 block; queue 20, active/IP 2, running job 2. Deployment có thể ghi đè. Tài liệu API Devspace ghi rollout active/IP 5 và worker 1; không coi đây là giá trị đã xác minh live. Câu UI “máy chủ xử lý tối đa 2 job” là chuỗi cố định, không lấy từ server.

TXT cần encoding được hỗ trợ; DOCX/DOC cần tài liệu hợp lệ, không mã hóa/password/macro/active content. DOC cần converter; ảnh cần OCR. Không hỗ trợ PDF và không nhận URL ảnh thay cho upload. Một số lỗi nội dung được phát hiện trong worker sau 202, nên phải đọc trạng thái cuối.

## 4. Legacy

Request dùng `LegacyRequest` linh hoạt. Ví dụ chuẩn để đối chiếu client cũ:

```json
{
  "user_id": "translate-test-user",
  "text": "Kiểm tra nhật ký bảo mật.",
  "source_lang": "vi",
  "target_lang": "en"
}
```

Nội dung còn nhận `message`, `question`, `prompt`, `content`, `messages`; đích có alias `language`. JSON trả `translated_text`, alias `translation`, `metadata`. SSE legacy dùng hạ tầng stream riêng; final có alias nội dung cho client cũ, không áp parser v3 một cách máy móc. Legacy có validation mã ngôn ngữ ISO 639-1 và đường chia đoạn riêng; không suy ra nó dùng capability/18 hướng v3. Kiểm legacy bằng API riêng nếu phạm vi yêu cầu tương thích client cũ, không ghi đã phủ legacy bằng test màn hình mới.

## 5. Lỗi cần đối chiếu

V2/v3 dùng `{"error":{"code":"...","message":"...","request_id":"..."}}`; legacy có thể dùng lỗi FastAPI `detail`.

| HTTP | Ví dụ v3 | Ví dụ v2 | Người test cần thấy |
|---|---|---|---|
| 400 | `INVALID_REQUEST`, `UNSUPPORTED_PAIR` | `INVALID_LANGUAGE`, `EMPTY_FILE` | Thông báo input không hợp lệ |
| 403 | `LANGUAGE_DISABLED` | — | Hướng chưa bật, không dịch được |
| 404/410 | Route không có khi v3 tắt | `JOB_NOT_FOUND`/`JOB_EXPIRED` | Kết quả không khả dụng |
| 409 | — | `RESULT_NOT_READY`, `JOB_FAILED`, `JOB_CANCELLED`, `IDEMPOTENCY_CONFLICT`, `JOB_ALREADY_FINISHED` | Không trình bày bản dịch giả là thành công |
| 413 | `TEXT_TOO_LONG`, `TOKEN_LIMIT_EXCEEDED` | `FILE_TOO_LARGE`, giới hạn ảnh/archive | Nêu giới hạn |
| 415/422 | `SOURCE_LANGUAGE_MISMATCH`, `UNSAFE_UNICODE` (422) | Loại sai (415), encoding/tài liệu/ảnh lỗi (422) | Nêu lỗi; lỗi worker nằm trong job |
| 429 | `RATE_LIMITED` | `RATE_LIMITED`, `QUEUE_FULL` | Chờ theo `Retry-After`, không gửi dồn |
| 502/503/504 | Kiểm đầu ra/model/timeout | Dependency/storage không sẵn sàng (503); worker có mã lỗi trong status | Không kẹt loading, có khả năng phục hồi |

## 6. Cấu hình và tuyến proxy

- V3: entrypoint `secai_gateway.multilang_app:app`, `MULTILANG_ENABLED=true`, các cờ `MULTILANG_ENABLE_EN`, `..._ZH`, `..._JA`, `..._KO`, `..._FR`, `..._DE`, `..._ES`, `..._RU`, `..._AR`. Model/tokenizer phải được cấu hình hợp lệ; bật flag không đủ chứng minh inference sẵn sàng.
- V2: `TRANSLATE_V2_ENABLED=true`; ảnh thêm `TRANSLATE_V2_OCR_ENABLED`, OCR URL/model; DOC cần converter. Worker phải chạy và dùng đúng store/artifact. Cấu hình chuyên biệt nằm ở `translation/settings.py`, v3 ở `multilang/config.py`.
- FE: `VITE_TRANSLATE_V2_FILES_ENABLED=true`; ảnh thêm `VITE_TRANSLATE_V2_IMAGES_ENABLED=true`. Đây là cờ build, sửa env không tự thay bản đã build.
- Client dùng `VITE_API_BASE` hoặc cùng origin. Vite proxy dùng `VITE_GATEWAY_PROXY`; static proxy `serve_static.py` dùng `TRANSLATION_GATEWAY_PROXY` hoặc `.translation-upstream` rồi fallback gateway. Chỉ đọc cấu hình cần thiết, không sao chép secret.

Test qua origin frontend để phủ proxy/SSE; chỉ khi chẩn đoán mới so với backend trực tiếp. Không restart/deploy hay sửa env để viết tài liệu này.
